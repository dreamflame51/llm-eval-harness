# Трассировка, и чем ей разрешено владеть

Спайк 17.09.2026, чтобы ответить на один вопрос: даёт ли платформа наблюдаемости
LLM (LLM observability) этому харнессу что-то, чего у него ещё нет?

Ответ — да, в одном месте и только в одном: **харнесс знает, что вышло из
прогона, и ничего не знает о самом прогоне**. Всё остальное, что предлагает
Langfuse, здесь уже сделано в git, и перенос стоил бы свойства, на котором
построен проект.

Английский оригинал: [tracing.md](tracing.md). Держать синхронными.

## Правило

> Трассировка наблюдает прогон. Она никогда не хранит число, которое кто-то
> отчитывает.

Каждое отчётное число — детерминированное чтение закоммиченного файла, которое
пересчитает человек с репозиторием и без модели (REQ-07). Сервер трассировки
хранит данные, которых нет в git и до которых CI не дотянется. Поэтому трассировка
— дополнение, выключенное по умолчанию, и ничто ниже по потоку не имеет права
стать от неё источником истины.

Конкретно — что остаётся на месте:

| что предлагает Langfuse | почему остаётся в git |
|---|---|
| оценки (scores) | `eval/expected_metrics.json`, закреплены равенством в тестах |
| очереди ручной разметки | ручные метки живут в YAML, а тест стережёт замороженный текст побайтно |
| управление промптами | `PROMPT_VERSION` входит в ключ кэша судьи, а кэш закоммичен |
| датасеты | `eval/ground_truth.yaml` процитирован из корпуса спан за спаном |

## Что она измерила, чего не мог никто другой

Три записи `live_check`, оттрассированные от начала до конца:

| спан | вызовов | всего | в среднем | самый медленный |
|---|---|---|---|---|
| `answer` — генерация | 3 | 156.7 с | 52.2 с | 63.8 с |
| `judge` — две оси на запись | 6 | 52.2 с | 8.7 с | 29.2 с |
| `retrieve` — dense + BM25 + слияние | 3 | 13.4 с | 4.5 с | 13.4 с |

Из таблицы сразу видны две вещи, и ни одна не была видна раньше:

- **Генерация — три четверти прогона.** У судьи два вызова на запись против
  одного у генератора, поэтому он выглядит дорогой половиной; это не так. Из
  тринадцати минут полного `live_check` около десяти — генератор. Настройка
  судьи не дала бы почти ничего.
- **Первый ретривал стоит 13 секунд, остальные — ничего.** Это BM25 строится по
  5 054 чанкам при первом использовании и кэшируется на коллекцию
  (`store.lexical_index`). Правильное поведение, ни разу не измеренное, и его
  стоит знать, прежде чем кто-то примет один медленный ретривал за проблему
  ретривера.

## Прогоны, а не вызовы

Запись ответов и замер дрейфа — две вещи в проекте, которые стоит сравнивать, и
ни одна не является одиночным вызовом. Их размечает `tracing.run()`:

- **Внутри процесса** он открывает корневой спан, так что двенадцать ответов
  записи приходят одним деревом, а не двенадцатью несвязанными трассами, с
  идентичностью прогона на нём — ретривер, генератор, `k`, размер чанка, выходной
  файл. Ровно этого не хватало, когда три записи одних и тех же двенадцати
  вопросов пришлось различать вручную ([#27](lessons.ru.md#27)).
- **Между процессами** он экспортирует имя прогона в окружение и ставит его на
  каждый прогон как `version`. `scripts/stability.py` нарочно запускает каждый
  повтор в свежем интерпретаторе — это и есть условие, которое он меряет, — так
  что повторы не вкладываются друг в друга, но могут нести одну метку:

```
version                    name              parent
drift 2026-09-17 10:22     drift run 1       root      <- дочерний процесс 1
                             answer          (вложен)
                             retrieve        (вложен)
drift 2026-09-17 10:22     drift run 2       root      <- дочерний процесс 2
                             answer          (вложен)
                             retrieve        (вложен)
```

Фильтр по версии собирает повторы; открыв один, видишь его дерево. Через него
идут и `record_answers.py`, и `stability.py`, а при выключенной трассировке
менеджер контекста — пустой `yield`.

## Как запустить

Трассировка — дополнение. CI ставит базовый набор и её не видит.

```bash
uv sync --extra trace
docker compose -f docker/langfuse/docker-compose.yml --env-file docker/langfuse/.env up -d
```

Compose-файл официальный, закреплён в репозитории, чтобы стек, давший числа
выше, можно было поднять снова. `docker/langfuse/.env` несёт значения для
безголовой (headless) настройки — организация, проект и пара ключей создаются при
первом запуске, без браузера и без аккаунта, — и лежит в `.gitignore`, потому что
локальный секрет разработки — всё равно секрет.

Затем, для одного прогона:

```powershell
$env:LANGFUSE_PUBLIC_KEY="pk-lf-harness-local"
$env:LANGFUSE_SECRET_KEY="sk-lf-harness-local"
$env:LANGFUSE_HOST="http://localhost:3000"
uv run python scripts/live_check.py --limit 3
```

Интерфейс — на `http://localhost:3000`. Без ключей в окружении
`llm_eval_harness/tracing.py` даже не импортирует SDK, и каждая команда ведёт
себя ровно как раньше — проверено: тесты и отчётные числа отказа совпадают с
установленным пакетом и без ключей.

**Ключи заданы, а стек остановлен — это нормальное состояние**, а не крайний
случай, поэтому оно обрабатывается, а не сопровождается предупреждением. До
защиты такая комбинация стоила каждой команде восьми секунд на выходе, пока
экспортёр повторял попытки, а затем печатала `Failed to export span batch` — что
читается ровно как поломка харнесса. Теперь это решает односекундная TCP-проба
при первом использовании:

```
tracing: nothing listening at http://localhost:3000, continuing untraced
```

и прогон идёт на полной скорости. Измерено: 10 с → 2 с на пробе, которая вообще
ничего не делает.

## Сколько стоил спайк, и одна ловушка в нём

Шесть контейнеров (web, worker, Postgres, ClickHouse, Redis, MinIO), около
16 ГиБ виртуальной машины Docker и примерно час. Сама инструментация — один
модуль и три декоратора.

Час ушёл не на код. Langfuse v4 перешёл на модель данных «сначала наблюдения»
(observations-first), и свежая собственная установка отвечает на старый
`/api/public/traces` фразой *«not available in events_only mode»*, а старая
таблица `observations` остаётся пустой. Оба чтения говорят «ничего не записано»,
и оба неверны: данные лежат в `events_core` / `events_full`, и интерфейс их
читает. Кто проверит запись, запросив таблицу, которую помнит, решит, что
интеграция сломана, когда она работает.

```sql
-- что на самом деле отвечает, на v4
select name, type, round(dateDiff('millisecond', start_time, end_time)/1000, 2)
from default.events_core order by start_time desc;
```
