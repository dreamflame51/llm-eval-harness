# llm-eval-harness

Небольшой RAG-пайплайн поверх пяти публикаций NIST и стенд, который меряет,
работает ли он на самом деле.

Смысл проекта — в измерении. Добиться выдачи, которая «выглядит релевантно»,
легко; стенд проверяет, действительно ли найденный текст **подтверждает** ответ
и отказывается ли модель, когда в корпусе ответа нет.

English: [../README.md](../README.md) ·
Журнал проблем: [lessons.ru.md](lessons.ru.md)

## Как устроено

```
PDF ──load_pdf──> текст ──chunk_text──> чанки ──> Chroma ──search──> топ k ──> LLM ──> ответ
```

| модуль | что делает |
|---|---|
| `loader.py` | PDF в текст (pypdf) |
| `chunker.py` | текст в чанки, окно 800 / нахлёст 160 |
| `store.py` | индекс Chroma, эмбеддинги `all-MiniLM-L6-v2` |
| `ingest.py` | собирает индекс из `data/corpus/*.pdf` |
| `pipeline.py` | вопрос в ответ, через Ollama |
| `dataset.py` | загружает `eval/ground_truth.yaml` |
| `validate.py` | проверяет, что фикстура ещё соответствует корпусу |
| `evaluator.py` | метрики ретривала |
| `refusal.py` | проверка отказов |

## Установка

Нужны Python 3.14, [uv](https://docs.astral.sh/uv/) и Ollama с `gemma4`
(только для генерации ответов; метрики ниже работают без неё).

```bash
uv sync
```

Пять исходных PDF лежат в `data/corpus/`. Собрать индекс:

```bash
uv run python -m llm_eval_harness.ingest    # ~5000 чанков, несколько минут
```

Они закоммичены намеренно: эталонный набор цитирует точные спаны именно этих
файлов, так что другая копия — или другое извлечение — сделает его невалидным.
Публикации NIST в общественном достоянии.

Индекс не коммитится. После смены модели эмбеддингов или размера чанка
пересобирать с нуля (`rm -rf data/chroma`): старые векторы несовместимы, а
`upsert` их не удалит.

## Команды

| команда | на какой вопрос отвечает |
|---|---|
| `uv run python -m llm_eval_harness.validate` | эталонный набор ещё валиден? |
| `uv run python -m llm_eval_harness.evaluator` | находит ли ретривал подтверждающий текст? |
| `uv run python -m llm_eval_harness.refusal` | отказывается ли модель, когда должна? |
| `uv run python scripts/smoke.py` | быстрая проверка глазами на трёх вопросах |
| `uv run python scripts/calibrate.py` | пересчитать порог дистанции |
| `uv run python scripts/stability.py` | воспроизводима ли оценка отказов? |
| `uv run pytest` | тесты стенда |
| `uv run pytest practice` | учебные задачи, вынесены из основного прогона |

## Эталонный набор

`eval/ground_truth.yaml` — 30 записей:

- **26 отвечаемых**: вопрос, эталонный ответ и точные спаны, которые его
  подтверждают.
- **4 на отказ**: корпус ответить не может, единственный правильный ответ —
  отказ. Два класса, считаются раздельно: `in_corpus_gap` (документ есть, факта
  нет) и `out_of_corpus` (документа нет вовсе).

Эталонные цитаты цитируют вывод `load_pdf()`, а не PDF таким, каким он выглядит
на экране. Артефакты извлечения сохранены дословно (`T he`, `process43`,
`Rivest-Shamir- Adleman`). Убирать их нельзя: ретривер индексирует именно
покорёженный текст, и «чистая» цитата засчитала бы корректный ретривал как
промах.

## Что показывают метрики

**`validate`** — целостность фикстуры. Два разных отказа, разделены:

| результат | что значит | что чинить |
|---|---|---|
| `MISSING` | цитаты нет в корпусе нигде | фикстуру |
| `SPLIT` | есть, но ни один чанк не держит её целиком | размер чанка / нахлёст |

Сейчас: 48 цитат из 51 чистые, 0 missing, 3 split.

**`evaluator`** — ретривал. Чанк засчитан, если содержит одну из эталонных
цитат записи.

| метрика | как читать | сейчас |
|---|---|---|
| `hit@5` | доля вопросов, где попадание было в топ-5 | **0.423** |
| `MRR` | среднее от 1/позиция; промах считается за 0 | **0.277** |

`hit@k` игнорирует позицию, `MRR` — нет: система, которая всегда ставит нужный
чанк пятым, для первой метрики идеальна, для второй плоха.

**Потолок: 24 из 26.** У двух записей единственная эталонная цитата, которую ни
один чанк не держит целиком, — засчитать их невозможно. Два промаха из
пятнадцати структурные, а не вина ретривала.

**`refusal`** — заземлённость. Доля неотвечаемых вопросов, на которых модель
отказалась.

| класс | сейчас |
|---|---|
| `in_corpus_gap` | 2/2 |
| `out_of_corpus` | 1/2 |

Отказ распознаётся по списку фраз, то есть метрика меряет заодно и сам список.
Неожиданную формулировку она засчитает как провал, а ответ, который сначала
отказывается, а потом всё равно выдумывает, — пропустит. Ровно поэтому отчёт
печатает каждый провальный ответ целиком.

Оставшийся провал настоящий и воспроизводимый: FIPS 197 в корпусе нет, но
SP 800-78-5 перечисляет размеры ключей AES, и модель отвечает по соседнему
документу вместо отказа.

`pipeline.py` декодирует жадно с фиксированным seed. Без этого оценка гуляла на
0.25 за пять одинаковых прогонов и не отличала регрессию от шума; проверить —
`uv run python scripts/stability.py`.

## Конфигурация выбрана измерением, а не на глаз

`800/160` и `all-MiniLM-L6-v2` получены перебором, где за раз двигался один
фактор, а текущая конфигурация была контролем:

| size / overlap | модель | hit@5 |
|---|---|---|
| 1000 / 200 | multilingual-MiniLM-L12 | 0.192 |
| 1000 / 200 | all-MiniLM-L6-v2 | 0.308 |
| **800 / 160** | **all-MiniLM-L6-v2** | **0.423** |
| 500 / 100 | all-MiniLM-L6-v2 | 0.308 |
| 300 / 60 | all-MiniLM-L6-v2 | 0.038 |

Последняя строка — в основном артефакт: при 300/60 достижимо всего 12 записей
из 26, потому что эталонная цитата обязана поместиться в один чанк. Перед
сравнением размеров чанка всегда считать потолок. Подробно —
[lessons.ru.md](lessons.ru.md) #6.
