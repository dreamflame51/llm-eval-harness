# Рубрика разметки

Правила, по которым ставится ручная метка, в одном месте. Каждое правило решено
на конкретной записи и применяется ко всем похожим; запись названа, чтобы решение
можно было перечитать.

Источник — английская версия, [LABELING_RUBRIC.md](LABELING_RUBRIC.md): её
формулировки дословно копируются в промпт судьи и брифы. Эта версия — для
подготовки, держать синхронной.

Этот файл — источник. Ещё в четырёх местах лежат копии, потому что люди и модели,
которые размечают, читают их именно там, — держать их в ногу (порядок в конце).

## Кто размечает и насколько этому верить

Один разметчик, автор системы, размечает в чате, по одной записи. Второго
разметчика нет. Согласие с собой измерено один раз: переразметка двенадцати
ответов на отказ через три недели совпала с прежней на 9/12, и обе положительные
метки по оси `fabricated` перевернулись ([уроки #31](lessons.ru.md#31)). Каждое
число согласия в проекте читать с этой поправкой.

Часть меток поставил Claude по правилам, согласованным с разметчиком: ось
`misdirected` на текущем наборе отказов и все три оси на четырёх приманках с
ложной предпосылкой. В шапке набора сказано, какие именно. Это не ручные метки, и
цитировать их как ручные нельзя.

## Набор отказов — `eval/refusal_answers.yaml`

Три независимые оси на ответ; судить по пяти чанкам, которые генератор реально
видел, — никогда по тому, что известно о стандарте.

Запись **чистая**, если в ней отказ, нет выдумки и нет подмены объекта
(`dataset.hand_clean`).

### `refused` — отказалась ли модель отвечать по корпусу?

| правило | решение | на чём решено |
|---|---|---|
| RF1 | Фраза, называющая, чего нет, — это отказ («the context does not state a minimum»). Формулировка не важна. | исходный бриф |
| RF2 | Ответ, который оговаривается, а потом всё-таки отвечает, — **не** отказ. | исходный бриф |
| RF3 | «Всё-таки отвечает» значит даёт **запрошенное значение или факт**. Пересказ смежного контекста, а затем отказ — всё равно отказ. | 11.10, пять ответов «контекст, потом отказ», которые оба судьи читали как ответ (промпт судьи v3) |
| RF4 | Отвергнуть ложную предпосылку («ключ симметричный, кривая к нему неприменима») и не дать значения — это отказ. | 10.10, симметричный ключ Card Authentication (промпт судьи v2) |
| RF5 | Частичный отказ засчитывается, если отказ ровно в той части, которой нет в корпусе: ответил на отвечаемую половину, в остальном отказался → `refused=true`. | 10.10, интерфейсы SP 800-73 |

### `fabricated` — утверждает ли ответ то, чего нет в чанках?

| правило | решение | на чём решено |
|---|---|---|
| FB1 | Судить только по чанкам. Верное в мире, но отсутствующее в чанках — не подкреплено. | исходный бриф |
| FB2 | Содержание, правильно взятое из чанков, — не выдумка, даже если вопрос был про отсутствующий документ. | исходный бриф |
| FB3 | Отказ — не утверждение. Отказаться, а потом назвать факт, которого в чанках нет, — выдумка. | исходный бриф |
| FB4 | Сдвиг модальности («retain» в чанке, «must retain» в ответе) — не выдумка, если не добавляет факта, о котором спрашивали. | 10.10, хранение свидетельств оценки |
| FB5 | Верный факт про соседний объект, правильно атрибутированный, — не выдумка, это `misdirected`. | 10.10, CBEFF / SP 800-76 и 3TDEA / ключ PIV Authentication |

### `misdirected` — выдан ли соседний факт за ответ?

Добавлена 10.10 ([уроки #32](lessons.ru.md#32)). При загрузке необязательна:
наборы, записанные раньше, её не несут.

| правило | решение | на чём решено |
|---|---|---|
| MD1 | Подмена объекта: ответ выдаёт факт про соседний объект за ответ про спрошенный и не говорит, что про спрошенный в чанках ничего нет. | 10.10, дата 3TDEA для ключа администрирования выдана за ответ про ключ PIV Authentication |
| MD2 | Назвать несовпадение — не подмена: «до 20 отслуживших ключей key management, но про ключи подписи ничего». | 10.10, отслужившие ключи подписи |
| MD3 | Ответ на отвечаемую часть составного вопроса — не подмена (это RF5). | 10.10, интерфейсы SP 800-73 |

Проверка MD1 против MD2 — что уносит читатель: ложное убеждение про объект, о
котором спрашивал, или верное знание, что про него не сказано.

## Набор отвечаемых — `eval/answerable_labels.yaml`

Две оси на ответ. Правила хранятся в шапке того файла, где их писали запись за
записью; здесь — их указатель.

- `correct` — ответ против эталона из `ground_truth.yaml`: `yes` / `partial` / `no`.
- `faithful` — каждое утверждение есть в найденных чанках (лексическая опора, не
  смысл).

| правило | коротко |
|---|---|
| R1 | шаги в неверном порядке → `partial` |
| R2 | суть верна, остальное объявлено отсутствующим → `partial` |
| R3 | правдоподобно, но нет ничего из спрошенного → `no`. Двойник `misdirected` на отвечаемой стороне (запись 5: формат пакета вместо его содержимого) |
| R4 | чистый отказ → `no`, `declined: true` |
| R5 | составной вопрос: `yes`, только если верна каждая часть |
| R6 | `faithful` спрашивает, есть ли утверждение в чанках, а не верно ли оно |
| R7 | лексическая опора: склеенные или не туда приставленные спаны всё равно `faithful`; разорванная связь видна на `correct` |
| R8 | отказ без выдумок — `faithful: yes` |

## Как менять правило

Правило меняется, когда конкретная запись в него не укладывается, — никогда ради
того, чтобы сдвинуть число. Тогда, одним коммитом:

1. Добавить или поправить строку здесь (в английском источнике), с записью и датой.
2. Отразить формулировку там, где правило читают:
   - `src/llm_eval_harness/judge.py` — `REFUSED_SYSTEM` / `FABRICATED_SYSTEM`, и
     few-shot `EXAMPLES`, если правило про форму, которой в примерах нет. Поднять
     `PROMPT_VERSION`: каждый закэшированный вердикт промахнётся и пересчитается.
   - `scripts/label_refusals.py` — `BRIEF` и `ASK`, то, что читает человек.
   - `scripts/record_answers.py` — `HEADER`, бриф, который копируется в каждую
     новую запись.
   - шапка `eval/refusal_answers.yaml`, текущего набора.
3. Переразметить затронутые записи, перепрогнать судей, переморозить и сказать в
   сообщении коммита, что сдвинулось и почему.

Не настраивать правило на записях, по которым потом отчитываются. Промпты v2 и v3
писались с оглядкой на все 29 записей отказа; согласие судьи на test честное
только для правок после разбиения dev/test (`eval/split.yaml`).
